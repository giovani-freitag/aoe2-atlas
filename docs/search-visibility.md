# Being found

One client-rendered page on a `github.io` subpath, against a Fandom wiki with a URL per
civilization. That is the whole situation, and it sets the ceiling before any of the rest of this
matters.

**Lost, and not worth chasing.** `aoe2 wonders`, `aoe2 wonder locations`, `age of empires 2
civilizations`. The Age of Empires Series Wiki already publishes an interactive Wonder-locations
map and a page per civilization, on a domain that outweighs this one by orders of magnitude. No
wording wins those. Empire-size comparisons belong to Britannica, Wikipedia and mapfight.xyz, and
are not about the game at all.

**Winnable, narrowly.** Which centuries each civilization is drawn in, what its Wonder is modelled
on, and which realms overlapped — as one table. That table did not exist anywhere: the wiki
tabulates civilization against Wonder with no dates, no cities and no territory, and the forum
thread that collects the dates collects them in prose and stops at forty-three of the fifty-six.
It is a handful of impressions, not traffic.

Sixteen of the seventeen languages are invisible to search and will stay that way. That is the
price of one URL, and it is the right price.

## What was done

| | What it actually buys |
| --- | --- |
| The game's name back in the title | The bundle rewrote `document.title` on mount with the wordmark and the tagline, and not one of the seventeen taglines names the game — so the title that gets indexed, which is the rewritten one, never contained the phrase every search for this thing contains. `app.documentTitle` now carries it in all seventeen. |
| `rel="canonical"` | `index.html`, a doubled slash and any tracking parameter an inbound link carries all answer with the same document. On a static host this is the only way to say which of them is the page. |
| The monument under each name in the roster | Doubles the page's crawlable text and puts fifty-six searchable proper nouns into the DOM. "Hagia Sophia" was the thing a reader arrived knowing and the one thing the list would not tell them without a tap. |
| [The civilizations table](civilizations.md) | The project's first page that is actually text, at `/civilizations/`, generated by `scripts/build-pages.ts` from the same files the map draws itself from. |
| A `Dataset` node in the JSON-LD | Google's Dataset Search is the only documented consumer for anything on this frontier. Zero effect on web ranking. |
| `theme-color` corrected to `#1a130d` | It was the splash colour, not the atlas's. |

Everything above except the title and the table is appearance, not ranking. Saying so plainly is
the point of this file.

## What was deliberately not done

Each of these was proposed, checked against current documentation, and dropped. They are recorded
so the next pass does not spend an afternoon rediscovering them.

**robots.txt** — would publish at `/aoe2-atlas/robots.txt`, which no crawler reads. The file must
be at the host root, and the host root is a 404 nobody here controls. Google treats a missing
robots.txt as "crawl everything", which is already what this site wants. It is *crawl* control
that is unavailable, not *index* control: `<meta name="robots">` in `index.html` works fine.

**sitemap.xml** — it would hold one `<url>`, and an unmaintained `<lastmod>` becomes a lie within
two releases. Worth revisiting only if the atlas ever gains real URLs.

**IndexNow** — announces URLs that appeared, changed or were deleted. There is one URL and it has
never moved.

**hreflang and per-language URLs** — hreflang annotates a *set* of URLs, and there is one. The cost
is not a router: it is seventeen HTML shells to keep in step with `index.html` on every head
change, hreflang in eighteen files, the app honouring a URL-derived locale ahead of
`navigator.language`, and a sitemap to get any of it crawled.

**A favicon set** — Google's favicon documentation says domain-level and subdomain-level home pages
are supported and subdirectory-level ones are not. No `<link>` under `/aoe2-atlas/` can put an icon
beside this result. (A `.ico` for older Safari tabs would be a different argument, not this one.)

**A web app manifest** — nothing in Google's crawling, indexing or appearance documentation
mentions one. It is an installability artifact, and it drags a 192px and 512px raster icon set back
in with it.

**56 pages, one per civilization** — the entire English fact corpus for all fifty-six is 656 words,
about twelve each, on an identical skeleton. Six are drawn on a single map, and twenty-one never
share ground with anyone, so the most interesting section would be empty on more than a third of
them. If it ever comes back, the only version worth building is the thirteen with something the
table cannot hold: the seven carrying an anachronism note and the six realms drawn by hand.

**19 pages, one per century** — 200 holds two realms. The rest is the same table sliced
differently.

**`FAQPage`, `HowTo`, `ItemList`, `BreadcrumbList`** — FAQ rich results stopped rendering in May
2026 and the documentation was deleted in June; HowTo was retired in 2023; `ItemList` carousels are
restricted to Course, Movie, Recipe and Restaurant; `BreadcrumbList` needs a hierarchy and there is
one URL. And inventing a FAQ section to justify markup is the wrong way round.

**`WebSite` with a `SearchAction`** — Google does not support site names at the subdirectory level,
the sitelinks search box was withdrawn in November 2024, and a router-less app has nothing for a
`SearchAction` to point at.

**`WebApplication` in the JSON-LD** — Google supports it for the Software app rich result, so a
node with no `offers.price` and no `aggregateRating` reports as an invalid item forever. Inventing
a rating to satisfy it would mean marking up something the page does not show.

**A `404.html` that redirects to the atlas** — GitHub Pages serves it with a 404 status, so it
manufactures no duplicate of the canonical page; there is no router, so there is nothing to route;
and every mistyped address would quietly open the atlas instead of saying the address is wrong.

**A `<noscript>` copy of the catalogue, or a colophon after `#root`** — both would be a second
hand-kept copy of text that already has a source of truth, and the colophon's content is already
rendered in the settings panel. The roster now carries the monuments from the data itself.

**Optimising for the LCP number** — it currently measures the 56px brand mark in the splash, not
the map, and reports 564 ms. A full prerender moved it to 2,060 ms while putting the map on screen
three and a half seconds sooner. Both pass, so the number cannot tell those two states apart and
must not be used to choose between them.

**Alt text on the civilization emblems** — `alt=""` beside a name that is already text is the
correct choice, not a defect. In `rivals.tsx` the emblem stands without a visible name, but the
button around it already carries an `aria-label` with that name, so the image needs nothing.

## What is left, and only the owner can do it

The site has no strong crawl path: GitHub marks both the repository sidebar's homepage link and the
README's link `rel="nofollow"`. Since 2020 that is a hint rather than a directive, and repository
pages are crawled heavily, so discovery is thin rather than blocked — but nothing points at this
URL with any weight.

1. **Search Console**, as a URL-prefix property for `https://giovani-freitag.github.io/aoe2-atlas/`
   with the trailing slash. A Domain property is impossible without DNS control over `github.io`.
   Verify with the HTML file method: Vite copies `public/` verbatim into `dist/`, so dropping
   `google<token>.html` there publishes it at the property root. Know what a path property will not
   have: the crawl stats and robots.txt reports are both host-level only.
2. **URL Inspection → Test live URL** on that address, then read the rendered HTML and the
   screenshot. It is the only direct way to settle what Googlebot makes of a page whose content
   arrives with the bundle.
3. **Request Indexing**, once. Repeating it does nothing.
4. **Bing** by importing the Search Console property rather than adding the site again.
5. **Two real links** — the Age of Empires forum thread that already hosts a static-image version
   of this map, and `Arkanosis/awesome-aoe2`. Both are nofollowed. They are worth doing for the
   people who would use the atlas, not for the signal.

None of that changes whether the page is indexable. It is the only way to find out whether any of
the rest of this worked.
